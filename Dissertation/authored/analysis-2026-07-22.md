## 3. The set-difficulty confound (most important finding)

In the clean group every FILTER run is set A and every BASELINE run is set B. The pooled
band table therefore mixes set difficulty into the condition contrast:

| Band | Base (=set B) | Filter (=set A) | Δ |
|---|---|---|---|
| clear | 10/12 (83%) | 8/12 (67%) | −17 pp |
| light | 29/42 (69%) | 16/30 (53%) | −16 pp |
| mid | 5/18 (28%) | 13/21 (62%) | **+34 pp** |
| heavy | 4/12 (33%) | 14/21 (67%) | **+33 pp** |
| full | 26/36 (72%) | 23/36 (64%) | −8 pp |

The +34/+33 mid/heavy "gains" are **set artifacts, not filter effects**: set B's mid/heavy bands
are dominated by 1–1.5 s traffic lights (see floors below) with baseline rates of 28–33%, while
set A's mid/heavy targets run 57–86% in both available set-A baselines (P1, PILOT1003). The
clean-group filter-A mid/heavy rates (62%/67%) are indistinguishable from set-A baseline —
i.e., within-set the filter appears roughly cost-neutral on the gradient, mildly negative in
clear/light. **The A/B split balanced class×region but not band×duration difficulty.** Fix
options: (a) recruit the BF cell hard so the confound cancels; (b) re-split the pool balancing
per-band duration; (c) analyse at target level with duration + dose as covariates (the planned
LMM does this naturally).

**Sensitivity re-run WITH P3 (2026-07-22, user request).** P3's pair is base=A / filter=B — the
reverse of everyone else — so including them softens the set confound (filter runs become 3×A+1×B)
at the price of spam-inflated filter hits (95% FA run):

| Band | Base | Filter | Δ (clean Δ) |
|---|---|---|---|
| clear | 10/16 (62%) | 10/16 (62%) | +0 pp (−17) |
| light | 32/52 (62%) | 23/44 (52%) | −9 pp (−16) |
| mid | 6/25 (24%) | 18/27 (67%) | +43 pp (+34) |
| heavy | 9/19 (47%) | 17/25 (68%) | +21 pp (+33) |
| full | 30/48 (62%) | 32/48 (67%) | +4 pp (−8) |

Same shape (mid/heavy positive, light negative), gentler clear/full deltas. Read with care in
BOTH directions: the confound argues the clean mid/heavy gains are set artifacts, while P3's
spam argues their filter numbers are inflated — neither group is decisive; the BF-cell
recruitment (§7.6) stays the real fix.

## 4. Duration dominates everything

Clean group, both conditions pooled: ≤1.5 s → **18%**; 1.5–3 s → 57%; 3–8 s → 67%; >8 s → 93%.
(With P3: 22% / 53% / 56% / 89% — same cliff.)
The ≤1.5 s targets are effectively unmeasurable for naive participants (they were fine for the
experimenter — authorship familiarity). 57 of 240 clean-group trials sit in that dead band.

**Floors confirmed today** (missed in every valid baseline pass):
- Set B (3 clean passes): ids 3, 22, 39, 40, 41, 50, 57, 67 — all ≤1.5 s; 6/8 traffic lights.
- Set A (P1 + PILOT1003 passes): ids 9, 16, 49, 61, 69, 76 (≤2 s) and **60** (person, 10.5 s,
  full-band — a genuine periphery floor, not a duration floor).

Recommendation: drop or down-weight ≤1.5 s targets (or extend the min-duration filter to 2 s)
and re-screen; expect naive baselines to land mid-band once the dead tail is gone.

## 5b. De-facto decoy analysis (added 2026-07-23, user design)

Authored person targets cross-referenced against the shipped build's baked YOLO track
(`Builds/StudyVideo/study_video.detections.json`) plus the runtime person acceptance
(`PassesPersonGate`: 3° min box height, 22.5° edge cone + 2.5°/° closeness widening, 6×4°
window). Three classes: **highlighted** (detected + passes the engine, ≥2 gated samples),
**detected-gated-out** (YOLO saw it, the cone/closeness engine rejected it), **never-detected**.
Gated-out + never-detected = de-facto decoys: the guidance system does nothing for them.
Counts: 33 / 15 / 3 of 51 pooled persons. Decoy ids — A: 15 (never), 12, 35, 52, 60, 61, 69,
70 (gated); B: 3, 13 (never), 4, 23, 42, 59, 62, 63, 66, 72 (gated).

**Within set A (same targets both conditions; base = P1 + PILOT1003, filt = P2/P33/P4):**

| Class | Base | Filter | Δ |
|---|---|---|---|
| highlighted | 32/36 (89%) | 43/54 (80%) | −9 pp |
| gated-out (decoy) | 7/14 (50%) | 10/21 (48%) | −2 pp |
| never-detected (decoy) | 1/2 | 3/3 | n≈0 |

**Read:** no differential suppression of system-irrelevant persons under the filter (50→48%).
The deferred-not-denied texture is visible at target level: persistent gated-out persons
(ids 12/35/52, 5.5–28 s) are 3/3 under filter; brief ones (61/69, 1–1.5 s) floor in both
conditions; the one counter-case is id 70 (6 s, −38° az): base 2/2, filter 0/3.

Caveats: (1) these are decoy-LIKE, not true decoys — the on-top ring is fully visible even on
unassisted targets, so this measures noticing an unhighlighted, dimmed region, not free
responding; John's Point 2 decoys (probes in unimportant regions, no ring salience asymmetry)
remain worth building. (2) The two on-disk bakes disagree badly (12/51 same class; the
DevVideos track calls nearly everything undetected — likely a UV/flip mismatch); the shipped
Builds track was used — **verify against the device copy on next pull**. (3) Set-A baselines
are P1 (FA-flagged) and PILOT1003 (rope probe) — the only ones that exist.
Script: session scratchpad `decoy_analysis.py`.

## 6. Block A (1-back) — at ceiling, procedure drifting

All eight runs (P1–P4, P33): go-accuracy 92–100%, commissions 0–3/57, median RT 593–776 ms.
P4's pending A1 = 98.4% fits. The three usable pairs split directions on RT (P2: Filter
719 vs NoFilter 683 ms; P3: NoFilter 776 vs Filter 678 ms; P33: Filter 608 vs NoFilter 667 ms —
2 of 3 faster under filter; P33 re-classified per §1). **Overall accuracy (hits+CRs / 83 scored
trials) favours the filter in all four assignable pairs** (P2 100 vs 97.6; P3 98.8 vs 96.3;
P33 98.8 vs 97.6; P4 100 vs ~98.4 — A1=NoFilter assumed from plan order and score is
experimenter-reported; P1 unassignable). Texture: filter rounds made ZERO commissions in all
four (errors were misses only); no-filter rounds carry the impulsive presses (P3 ×3, P33 ×1).
Each delta is 1–3 trials at ceiling (4/4 sign test ≈ .06 one-sided) — directional, not
confirmatory; the ceiling fix below is what would let this express itself. **Accuracy has no headroom for any
filter or distractor effect** (John's Point 5a ceiling warning realised). Options: 2-back,
shorter SOA (<2.5 s), more/lure no-gos — pick one, pilot once, lock.

Procedure: P2, P3 and P33 ran CPT rounds inside their arms' windows (P33 by experimenter
report — no rest taken, arm advanced between rounds, final X skipped; see §1). P1 and P4 ran CPT
after both arms were X'd closed. Add to the run script: *start CPT round → finish → then press X; repeat for
second arm.* The pid/time cross-check works and catches all of this — keep it.

## 8. What today established

- The full pipeline (AutoSession → ledger → CPT tool → pull → analysis) survives real naive
  participants end-to-end; five sessions in one evening.
- The yellow on-top probe is measurable in BOTH conditions for naive users (no floors, no
  black-ring inversion), baselines 52–78% around the 60–85% band.
- The filter does not wreck detection (paired deltas −8..+7 pp) and tends to speed RT — an
  attention-marker probe result consistent with the funnel doing its job without blinding.
- The binding constraints are now **stimulus-side** (short-target floors, set-difficulty
  asymmetry, n-back ceiling), all fixable before the formal pilot gates.
